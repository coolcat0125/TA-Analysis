## 3. 匹配规则（车系锚定）

### 3.1 归一化 `norm()`

小写 → 去除空格/连字符/下划线/`·`/`.`/括号/(半角全角 `/` → 去除`新能源` 三字。
（与既有 `fill_sales.py` 的 `norm()` 保持一致，作为基线；扩展时不得改变既有行为。）

### 3.2 通道（按优先级，命中即停）

1. **A 精确**：`norm(通用名称)` == `norm(seriesname)`。
2. **B 品牌+名称**：`norm(产品商标去牌/汽车) + norm(通用名称)` 与车系名**双向包含**，且品牌词
   出现在车系名中（品牌守卫）。
3. **C 分词**：`通用名称` 按 `,，、;；/` 分词，任一分词与车系名双向包含且
   `min(len)>=4`；候选唯一才采纳。
4. **D suggest 兜底**：`sou.api.autohome.com.cn/sug/_suggest`（`media_fill.py` 已有实现与
   `brand_conflict` 品牌守卫）解析出 `seriesid`；**该 seriesid 必须在当期榜单内**才采纳。
5. **多候选 → HOLD**：记入 `_pending_naming` 台账 + 底表 `销量覆盖状态=未匹配-命名待锚定`。
   **严禁**用最短/最长/第一个候选硬填（AGENTS 2026-09-17 泛化名撞名教训）。

### 3.3 冲突与守卫（沿用既有教训）

- 跨企业 = 必错；同集团不同品牌（上汽/荣威/名爵）= 错系 → 均拒绝。
- 占位符通用名称（`PLACEHOLDER_GENERIC_RE`，如"纯电动轿车""插电式混合动力多用途乘用车"）
  **不参与匹配**，直接判 `无车系身份`。
- 品牌短词（≤2 字）不得单独作为匹配依据。

## 4. 行级 vs 车系级（**防重复计数铁律**）

- 底表一行 = **一条公告车型记录**；同一车系跨批次/跨动力类型变体会有多行。
- `月销量(辆)` 是**车系级**指标，同车系多行**共享同值**。
- **任何汇总统计必须以「车系」为统计单元**（按 `车系ID` 或归一化车系名去重后加总）；
  对底表行直接 `SUM(月销量)` 会重复计数，**明令禁止**。
- 所有销量相关图表/表头/脚注必须写明：
  「车系级口径，已去重；底表行级值仅供单行参考，不可加总」。

## 5. 覆盖率披露（三口径 + 分桶）

必须同时给出并写入交付物：

1. **行级覆盖率** = 已填行 / 5,392
2. **车系级覆盖率** = 已匹配独一无二车系数 / 底表去重通用名称数（剔除 `无车系身份`）
3. **在售车系覆盖率** = 已匹配车系数 / （已匹配 + 未匹配-命名待锚定）
4. **未覆盖分桶计数**：`无车系身份` / `未匹配-已停产或未上量` / `未匹配-命名待锚定` / `未匹配-无车系ID`

> 未覆盖 ≠ 数据质量缺陷。历史批次（341~410 批，2021–2026）中大量车型已停产，
> 在 2026 年月度榜上无销量是**语义正确**。报告必须把这一层讲清楚，否则会被误读为"数据缺失"。

## §11 车系级聚合与分类规则（canonical · 2026-10-19 Lead 仲裁）

> 本节为唯一口径定义。JSON / 交付物 / 报告凡引用车系级分类字段，一律按本节；不得各自实现。

### §11.1 聚合规则

| 字段类型 | 规则 | 并列处理 |
|---|---|---|
| 分类型（细分市场 / 动力类型 / 企业名称 / 产品商标） | **众数（mode）** | **取字典序最小** |
| 数值型（续航 / 容量 / 电耗 / 整备 / 功率 / 能量密度） | **中位数（median）** | — |

**可复现证据（Lead 独立复算，零差异）**：`by_oem` 按「众数 + 并列取字典序最小」逐位复现 link-engine 的
比亚迪汽车工业 203,342 / 浙江吉利 84,222 / 零跑 66,257 / 特斯拉(上海) 64,837 / 上汽集团 47,067 / (未定) 41,542，合计 797,701。
（按「首次出现序」并列处理会得到 193,825，**错误**；该差异已归因并作废。）

**空值先剔除，不参与众数计算**；仅当该车系的全部标签均为空时才归 `(未定)`。**不得**以 `None` 作为分类键（`None` 与字符串键在分组/序列化时行为不同）。

> 反证（Lead 实测）：若把空值当成一个真实取值参与投票，`by_oem` 的 `(未定)` 会从 41,542 虚增到 **78,328**、CR3 由 44.36 错算为 **42.01**、n 由 54 变 52 —— 这是「多数行未填」的车系被误判为未定，不是数据事实。

### §11.2 动力类型三分（R1，canonical）

```
行级 label = "EREV"  若 是否增程(EREV) 列取真值（1/是/True）
             else "BEV"  若 动力类型 含 "BEV"
             else "PHEV"
车系级 = 行级 label 的众数（并列取字典序最小）
```

**结果（2026-09 已锚定口径）**：BEV 523,457（165 系，65.62%）/ PHEV 231,121（101 系，28.97%）/ EREV 43,123（16 系，5.41%）。

**被否决的 R2**（任一行为增程 → 整系 EREV）产出 BEV 484,409 / PHEV 219,530 / EREV 93,762。否决理由三条：

1. R2 会把 **16 个「混合动力家族」整体搬进 EREV，合计 50,639 辆 = 已锚定的 6.35%**（问界M9 10,262、零跑C10 10,103、问界M6 8,651、零跑C16 6,146、极氪7X 5,544、零跑C11 4,341、五菱宏光新能源 2,339、问界M8 1,216、享界S9T 766、eπ007 476、智界R7 467、锐胜M8新能源 145、深蓝G318 99、星海S7 63、岚图FREE 14 等）。这些车系**同时有纯电版与增程版**（零跑C11 32 行、问界M8 22 行），单一标签本就不能表示；行级众数是最小失真聚合。
2. 与 `meta.dedup_rule`「分类型取众数」自相矛盾 —— R2 是该规则的破例。
3. R2 会被**单行脏标记放大**：`极氪7X` 为纯电车型却带增程行，用「任一为真」会把整系 5,544 辆判为 EREV。**宁要正确的小数，不要被单行翻转的大数。**

**强制披露**：`structure.mixed_energy_families` 必须给出混合家族清单（车系名 + 销量 + 占已锚定比例）；报告与演示稿须写一句「同车系同时提供纯电与增程版本者，按公告行级众数归入其一」。
