# 核定底表 · 更新运行手册 v1

> 场景：新批次公告发布（如 412 正式、413 批）或源表重制后，刷新核定底表。
> 全部命令在 `01-主仓库/TA-Analysis/核定底表/` 下执行；脚本目录 `scripts/`。

## 流水线（按序执行）

```bash
cd "D:\#AI\00 Project\17 TA analysis\01-主仓库\TA-Analysis\核定底表"

# 0) 开工检查（17 AGENTS 并行纪律）：确认无自动化在写、源表 mtime 正常
#    诊断基线：错配率、三方对账、归一化残余（产出 data/diag_report.md）
python scripts/diag_master.py

# 1) 官方锚点（若新批次有扫描底表，先更新 common.py 的 SCAN_XLSX 路径）
python scripts/fetch_official.py        # → official_anchors.json + coverage_report.md

# 2) Track B 自动取证（增量：已缓存 OK 的跳过；断点续跑）
python scripts/fetch_evidence.py        # 全量补新；--group byd 单集团；--retry-miss 重试失败

# 3) 台账合并（分歧 → data/car_len_review.md）
python scripts/merge_ledger.py

# 4) 人工仲裁（只改 data/car_len_overrides.json，键=group|series；改完重跑 3）
#    {"byd|秦L": {"len": 4830, "wb": 2790, "conf": "B", "src": "人工仲裁",
#                 "url": "https://...", "note": "依据：xxx"}}

# 5) 构建底表（幂等）
python scripts/build_master_table.py    # → data/NEV公告核定底表*.xlsx/csv/json

# 6) 校验（FAIL 清零才收工）
python scripts/verify_master.py         # → data/verify_report.md；exit 1=有 FAIL
```

## 新批次接入清单

1. **17 侧先行**：新批次正式公告并入合并版 xlsx（或出新的扫描目录）——爬取/合并属 17 主力终端职责。
2. `common.py` 更新路径常量（SRC_XLSX / SCAN_XLSX）。
3. 新批次车系先过 `series_norm`（新前缀/别名 → 补 `series_norm.PREFIX` 或 alias 台账）。
4. 跑 1→2（只补新车系，缓存增量）→3→4→5→6。
5. 收工：向 `01-主仓库/TA-Analysis/PROJECT_STATUS.md` 迭代记录追加一条（17 AGENTS 规则 6）。
