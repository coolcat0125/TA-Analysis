## 一、明细全量（xlsx 首表 / CSV / JSON.rows）

一行 = 一条公告型号记录（含合资、公示、清单补充，全保留）。

### 公告原始层（原样保留，不修改）
| 列 | 说明 |
|---|---|
| 批次 / 年份 | 公告批次号；年份=批次→年映射（341-352→2021…401+→2026，约12批/年） |
| 状态 | 正式 / **公示**（412 批，默认排除一切统计）/ 清单补充（409-410 新增清单合成行，model 以 NEW- 开头） |
| 产品型号 | 公告型号（主键级；清单补充行为合成码） |
| 产品商标 / 企业名称 | 归属判定输入 |
| 通用名称 / 车系原始名 / 车型名称 | 车系名相关原值；「通用名称」可能是多别名拼接/产品类型占位 |
| 产品类型 / 细分市场 | 原值（细分市场与车长存在已知不匹配，仅参考） |
| 动力类型(原) / 统计动力类 / 增程 | 原值→归一类：BEV / PHEV / **EREV**（是否增程=是 或 名含增程）/ HEV-ICE（HEV 铁律归 ICE 类）/ FCEV / 其他 |
| 续航(原) / 容量kWh / 容量(原) / 电池类型 / 能量密度 / 电芯供应商 / 电池包供应商 / 整备质量 | 公告参数原值；容量kWh 为解析值 |
| 轴距(公告) / 车长(公告) | **公告列原值——已知被媒体共识传播污染，勿直接用于分析**（见 diag_report D1） |
| 来源URL | 411/412 行=官方公示 art 详情页；其余为空 |

### 核定层（可分析）
| 列 | 说明 |
|---|---|
| 集团 / 板块 | 12 家集团口径（先商标后企业名；乐道/萤火虫=蔚来集团独立板块） |
| 合资剔除 | 是=命中集团但属纯合资（关键词级或实体级），留行不入 12 家统计 |
| 主口径内 | 板块 ∈ MAIN_BOARDS（矩阵分节口径） |
| 车系主名 | 归一化主名（品牌前缀剥离/大小写/零宽字符/短代号补前缀/别名台账合并）；通用名称为产品类型占位时置空 |
| 车长(核定) / 轴距(核定) | 台账值（详见台账 sheet）；**未核定=空，不猜** |
| 车长来源 / 车长置信 / 车长核验 / 车长证据URL | 官方411公示(A) / 官方412公示(A) / 汽车之家在售(B) / 15迁移种子(B/C) / 未核定；核验=一致/代际多值/分歧/人工仲裁 |
| 电压等级(补值) / 电压置信 | **补值非公告**（平台+公开配置推断），待核实=未命中 |
| 数据质量标志 | 分号连接：无容量 / 容量续航矛盾 / 质量车长比出界 / 电量密度出界 / 系公告车长混乱 / 通用名称为产品类型 |

## 二、12家统计视图

按集团：全行(含合资/公示) / **有效行**（12家内×非合资×BEV/PHEV/EREV×有容量×无矛盾）/ 动力类分布 / 车系数 / 核定覆盖率 / RESS线n(对账) / H1用户给数。

## 三、车系主数据

集团×车系主名：板块、动力类、全行/有效行、首末批、核定车长及来源、公告原始名写法（去重计数）。

## 四、车长核定台账（car_len_master.json 同步）

| 字段 | 说明 |
|---|---|
| len / wb | 主长度/轴距（当前在售代际） |
| conf | A=公告官方 art 页；B=汽车之家参数（权威媒体）；C=单一来源待复核；null=未核定 |
| src | 官方411公示 / 官方412公示(公示) / 汽车之家在售 / 15迁移种子 / 人工仲裁 / 未核定 |
| url | 证据链接（A/B 必有） |
| cross | 一致 / 代际多值(在售X/公告众数Y) / 分歧 / 人工仲裁 |
| alts | 各来源出现过的其他代际长度（换款真实差异，非错误） |
| verified | 核定日期 |

人工仲裁通道：`data/car_len_overrides.json`（`group|series → {len,wb,conf,src,url,note}`，merge_ledger 最后应用，判断留痕可复跑）。

## 五、别名台账（series_alias_master.json）

归一化后的公告异写 → 车系主名（如 宋PLUSEV/比亚迪SONGPLUS→宋PLUS；MODEL3→Model 3；EQ1→小蚂蚁）。

## 六、批次覆盖 / 剔除与存疑 / 口径说明

批次覆盖=逐批全行与有效行；剔除与存疑=全部 dq 标志行留档（不静默删除）；口径说明=铁律与口径要点（随构建刷新日期）。
