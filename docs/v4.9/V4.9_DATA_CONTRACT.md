# TA-Analysis v4.9 Data Contract

## 1. Purpose
This document defines the minimum shared data semantics for multi-Agent development.

The contract prevents different Agents from creating incompatible representations of the same vehicle, supplier, parameter, source, or inference.

## 3. Status vocabulary
Use only these states unless an extension is documented:
- unknown
- candidate
- verified
- inferred
- conflicted
- rejected

Do not collapse inferred into verified.

## 4. Evidence levels
- A: official primary source.
- B: high-quality industry/database/research source.
- C: professional media/platform.
- D: inference.

## 5. Source precedence
A > B > C > D.

A weaker source cannot silently replace a stronger verified source.

Conflicting sources must be retained in evidence records and resolved explicitly.

## 6. Units
Canonical engineering units:
- battery capacity: kWh
- voltage: V
- energy density: Wh/kg
- pack mass: kg
- motor power: kW
- motor torque: N·m
- motor speed: rpm
- dimensions: mm

Raw source values may be preserved separately where needed.

## 7. Inference rules
Inference is allowed only when:
1. the inference rule is documented;
2. source records used by the inference are retained;
3. result is marked inferred;
4. confidence/rationale is retained;
5. the value cannot be mistaken for a directly disclosed fact.

## 8. Candidate vs master
Candidate tables are staging areas.

The canonical/master layer accepts a value only after its applicable validation gate passes.

No Agent may use a candidate value as a verified fact in downstream reporting.

## 9. Relationship model
Preferred relationships:
Vehicle -> Battery -> Cell Supplier
Vehicle -> Electric Drive -> Motor Supplier
Entity/Field -> Evidence
Supplier -> Product -> Application Vehicle

## 10. Schema-change rule
Any Agent proposing a field rename, type change, unit change, status change, or relationship change must:
1. update this contract;
2. document migration impact;
3. provide backward-compatibility or migration logic;
4. run regression QA.

## 11. Quality invariants
- IDs are unique;
- supplier canonical names are normalized;
- vehicle-to-supplier mappings are auditable;
- no evidence-free verified value is introduced for a new v4.9 field;
- no cross-brand propagation;
- no silent unit conversion;
- no loss of prior verified information.
