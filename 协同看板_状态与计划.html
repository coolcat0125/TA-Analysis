23:00

            
夜间自动轮

            
批次监控 check_new_batch → 循环补全（media_fill → fill_logic → fill_consensus → reconcile）。收敛条件：每轮新增 < 25 格或到 06:00 止；不改 CHANGELOG、不推送。

          

          

            
23:00 → 06:10

            
夜间监管轮

            
独立监管角色值守，跑 8 个检查点，全程 零底表接触、监管写库 0 次；02:25 与 05:26 做双源独立 verify 快照互证，06:00 总复盘收尾。

          

          

            
06:10

            
白天分派

            
监管轮定稿《Update/夜间分派_YYYYMMDD.md》，把夜间发现拆成 D1–D4，每项固定五要素：任务 / 目标 / 验收 / 禁区 / 依赖。

          

          

            
白天

            
主力终端承接

            
执行需真实浏览器通道或人工审批的尾巴（如 411×13 电芯回填、公示查询列交互）；当晚再回流给夜间轮做批量执行。

工作循环（SYNC.md）

          

            
1
开工同步
跑 sync.ps1 只快进，确保基线最新

            
2
干活
只补空、唯一共识、逐格台账、版本递增

            
3
收工三件套
底表 / 两版看板 / audit-output 刷新 + CHANGELOG 登记

            
4
冲突预防
push 前必 pull --rebase；长任务先看远端 HEAD

          

        


        

          
四条协同约定（PROJECT_STATUS §3）

          

            
A
上传防冲突
PUT 前 GET 远程 SHA，核查对方改动再动手

            
B
只补空原则
不覆盖已有值；"不适用(BEV)" 占位不可补

            
C
版本登记
改动进 CHANGELOG 取下一版本号；版本号只增不减

            
D
历史教训
同名版本曾互覆盖 → 以对方底表为基座无损合并
