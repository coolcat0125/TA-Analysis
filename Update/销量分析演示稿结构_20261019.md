### 2.6 替换式刷新「命中率」普查（阶段 1 追加 / 2026-10-19）

**结论：7 条真实替换意图全部 0 命中（命中率 0/7），唯一"命中"的是无副作用的占位项。** 即现稿的正文口径数字**不是**由这条刷新路径写进去的，而是某次一次性修复/其他通道写入的——该路径目前已整体失效。

**根因（两个，需分开对待）**：
1. **替换源一次性的本质**：替换源是"上一版字面量"。首次替换成功后，源字面量在文件中即永久消失 ⇒ **第二次运行必然 0 命中，且设计与实现都无任何告警**。这是"非幂等刷新"的固有缺陷，不能靠补更多替换对来治。
2. **千分位/空格字面量不匹配**：现稿中该数量词有 `5,392 款` 与 `5392款` **两种形态**（有逗号 4 处、无逗号 68 处）。任何按单一形态书写的替换源只能覆盖其中一类；A4/A6 正是死于形态差异。

**阶段 2 施工要求（写入本清单，验收须逐条核对）**：
1. **不再新增替换对**。新增页与刷新页的数字一律走**派生注入**：从 JSON / 底表算出值 → 直接写入目标 run（`run.text = f(...)`），源侧不做字面量匹配。
2. 对既有 `GLOBAL` 块：**要么删除**（承认其已失效、避免"看起来在刷新"的假象），**要么改为正则替换 + 命中计数断言**（`re.subn` 计数，命中 0 时抛错而非静默跳过）——推荐后者仅用于历史遗留页，新页不适用。
3. **千分位形态统一**：口径文案中的数量词统一为带千分位 + 空格分隔（`5,392 条`），并在阶段 2 对现稿做一次形态归一（把 68 处 `共5392款` 归一到 `共 5,392 条`），消除双形态。
4. **硬失败断言**（自检 → 门禁）：刷新后重开 pptx，逐项断言 ①列数文案 == 底表实际列数 ②数量词与底表行数一致 ③无残留旧字面量（对 `4,613`/`v4.3.x`/`v4.9.2x` 之外的**任何**过期版本号做正则全稿扫描，命中即抛错）。
